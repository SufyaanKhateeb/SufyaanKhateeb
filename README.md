## On my reading desk: DDIA 📖

I'm exploring **Designing Data-Intensive Applications** to connect the systems I work with to the ideas behind them.

Questions I want to dig into:

- What changes when a database needs to serve more than one machine?
- Which guarantees do transactions, replication, and messaging actually give us?
- How do retries, duplicate events, and partial failures shape a system's design?
- When does an architectural choice make a system simpler to maintain?
